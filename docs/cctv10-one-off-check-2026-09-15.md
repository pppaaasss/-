# CCTV-10 九个地址的单次家庭检查

用户在试用历史源后明确要求“先测一下”此前提到的九个地址。新增手机动作 `check-cctv10`，单次从 AC86U 实测，作为用户授权的定时窗口外专项检查。

范围固定为本次 GitHub 家庭档案中的两个历史地址及七条候选：原源 183.129.255.66、刚切入的 101.66.195.43、115.48.161.223、101.66.194.200、101.66.195.190，以及同一咪咕线路四个不同日期的完整签名 URL。九个 URL 不等于九条独立线路或九个合格备用。

手机仅运行 Python 和 SSH，路由器执行已经安装的原生 sampler。每批三条、最多三批，每批 240 秒；每条最多三层 HLS 清单及两段 6 MiB 样本。沿用 worker 锁、50/58 MiB 可用内存门槛、16 MiB 进程组 RSS、75% CPU 限制、电视路径的流量标记及清理。忙碌或资源不足时报告未完成并停止，不伪装为频道故障。

输出每个地址的 HTTP/curl 错误、两段下载结果、最低下载速度，以及可计算时的节目码率和余量。非 HLS、加密等不支持的响应保持未知；此检查不解析分辨率、帧率或频道内容，不能授予自动合格资格。结果保存在手机 `~/cctv10-check.json`，用户可发截图或 JSON 继续分析。

此动作不修改定时任务、正式台单、云端历史或自动发布记录，不需要 GitHub Token，不启动路由器 Python，不安装工具，不依赖 mktemp。安装及诊断的 13 项针对性测试通过，包括真实原生二进制处理本地 HLS、403、HTML 响应、缺失结束记录和已有 worker 忙碌。
