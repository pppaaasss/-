## 格式兼容

`adminouyang/TV` 与 `czerov/iptv-api` 的清单在 `$` 后附加 `订阅源` 或 `山东联通11` 一类显示备注。原解析器把备注保存在请求参数字段，而家庭调度不接受非空请求参数，导致大量地址无法排入检测。

仅对这两个确切的上游入口，清除完整匹配的 `订阅源` 和省份+运营商+数字备注。URL 本身不变；真实 HTTP 参数、混合字符串、未知后缀以及其他上游的后缀保持原有处理。这样相同频道和地址沿用无参数候选 ID，可与已有永久检测历史去重。

## 800 条补源规则

00:30 的定时任务先读取同一份 `home-control` 提交中的持久化队列、永久检测历史和交付回执，并合并与当前正式台单绑定的待交付候选。

- 可调度且未测的新源不足 800 条：从已配置上游抓取一次最新文本，按原流程去重、构建候选并交付。
- 达到或超过 800 条：跳过上游采集和候选清单重写，直接使用已有队列，02:00 开始家庭检测。
- 数量按家庭调度规则计算；已测、重复、被反馈否决、串台地址冲突、需要额外请求参数的地址不用于凑足门槛。失去当前正式台单绑定的待交付清单不计入。
- 800 是补源门槛，不是每晚检测上限。超过 800 条也继续按原窗口和预算清队列。
- 抓取后仍不足 800 条也会检测已有候选，不会等凑满才开测；窗口仍为 02:00–11:00，未完成队列按现有机制续跑。

对应实现为 `scripts/plan_home_harvest.py`，在工作流摘要中报告待测数量和是否补源。本次为 GitHub 采集端更新，无需路由器升级。
