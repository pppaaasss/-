## 路由器更新

当前 AC86U 的每 5 分钟入口及 08:00 截止逻辑保存在本机，修改 GitHub 无法自动覆盖。因此新增手机管理动作 `poll30`，更新这一项定时任务、开机恢复块和已安装入口的上午时段：每分钟触发一次原入口，30 秒后再触发一次，凌晨窗口延长至 11:00。

原生 guardian 的锁继续阻止重叠采样，内存、CPU、单批时长和单批流量上限不变。窗口外不启动采样。13:00 和 20:00 的入口继续用于现用源检查，云端不派发新候选或备用源采样。

手机在 Termux 下载本次提交的 `router/ac86u/native/native_from_termux.py`，执行 `python 文件名 poll30`，输入一次路由器 SSH 密码。不需要重新输入 GitHub Token，也不重新安装采样器。更新前核对启动块、原 cron 和已知入口文件摘要，备份至 `/opt/var/lib/iptv-home-native/before-poll30`；写入或 cron 更新失败时恢复原配置。更新后核对两个文件及 cron，成功标志为 `POLL30_OK`。不认识的本机修改会被拒绝覆盖。

在用户执行并返回成功前，只能确认新源时段限制在云端生效，不能声称本机已经改成 30 秒或延长至 11:00。

## 18:48 手机更新失败修复

用户截图显示下载及 SSH 登录成功，随后两次 `NATIVE_ERROR:checkpoint_rename`。旧 poll30 从 `/opt/tmp` 直接调用原生 `rename(2)` 写入 `/jffs/scripts/services-start`，跨文件系统会失败；恢复也用了同样的路径，可能导致原生入口已延长、cron 仍保持旧值。

修复：所有更新和恢复先用 `mktemp` 在目标文件同目录创建临时文件，复制、设权后才执行原生 fsync/rename；每个恢复动作独立执行，单项失败不阻断其他配置恢复。成功恢复输出 `POLL30_RESTORED`，恢复异常输出 `POLL30_RESTORE_FAILED`。再次执行 poll30 会识别旧版或已延长的原生入口，不需要重新安装或输入 Token。

验证使用实际编译的原生二进制，在 `/dev/shm` 与 `/tmp` 两个文件系统间复现 `checkpoint_rename`，随后运行生成的 shell 验证更新成功、部分更新后的重试、写入失败恢复、cron 失败恢复和临时文件清理。
