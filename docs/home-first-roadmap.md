# 家庭优先电视健康系统迁移路线图

> 当前工作分支：`home-first-ac86u`
>
> 起点提交：`ceeb4d7f6b9206811d8ae7c193930182409a3094`
>
> 最终原则：GitHub 只搜集和发布；AC86U 从家庭实际分流路径检测并拥有唯一裁决权；香港主机不参与检测、中转或替换。

## 已确认的运行规则

- 所有时间均按家里路由器的北京时间（`Asia/Shanghai`）。
- 每天 `02:00` 执行主检：拉取 GitHub 当日新增/变更候选，检测候选能否成为家庭备用，同时检查全部央视和省级卫视正式线路并按需替换。
- 每天 `13:00` 执行复检：只检查央视和省级卫视正式线路；需要替换时，先在家快速复验已有家庭合格备用。
- 废除每 6 小时巡检、每 72 小时深检和每 3 天统一轮换。线路合格就保持，不为轮换而轮换。
- 没有频道替换数量上限；同一轮不合格多少台，就处理多少台。
- GitHub 抓到的线路只能进入“候选池”，不得直接成为正式或备用线路。
- 只有 AC86U 从与 Apple TV 等价的 DNS、出口、分流和 IPv4/IPv6 路径验证通过后，候选才能进入“家庭合格备用池”。
- 香港的成功或失败证据权重均为零。
- 家庭断网、GitHub 不可达、报告不完整、路径未经确认、路由器资源不足或出现大面积同时失败时，保持上一份正式清单，禁止替换。
- 用户在电视上确认的卡顿、模糊、串台或错误频道，拥有最高优先级并可否决自动结果。

## 数据边界

| 数据 | 产生位置 | 含义 | 能否触发替换 |
|---|---|---|---|
| GitHub 候选池 | GitHub Actions | 新搜集、已分类和去重，但未经家庭验证 | 否 |
| 家庭合格备用池 | AC86U | 在家庭实际路径通过连续分片和质量检测 | 可以，切换前仍须快速复验 |
| 家庭正式线路报告 | AC86U | 当前央视和省级卫视在家中的真实状态 | 可以 |
| 用户反馈 | 家中实际观看 | 卡顿、清晰度和频道身份的最终证据 | 可以，优先级最高 |
| 香港检测报告 | 香港主机 | 与家庭使用目标无关 | 永远不可以 |

每阶段必须满足：独立提交、测试结果写入本文件、能够安全停在该阶段、不得在验证前改动四份正式播放清单。

### 3. 家庭唯一裁决与替换引擎（已完成）

- [x] 当前线路同一轮连续失败且家庭网络基线正常后，才允许判定不合格。
- [x] 候选必须通过连续视频分片、下载余量、真实分辨率/编码和最低码率检查。
- [x] 正式切换前快速复验家庭备用，过期备用不得直接使用。
- [x] 单份家庭报告可产生不限频道数的替换决定；路由器本身不修改正式清单。
- [x] 无合格备用时只记录待处理，不使用香港或 GitHub 云端存活结果兜底。
- [x] 家庭备份有效期为 36 小时；`02:00` 优先复检将在 18 小时内到期的备份，GitHub 候选拉取失败也不影响本地备份维护。

阶段测试：家庭契约、裁决、探针和安装相关 32 项全部通过。全仓库共 182 项，165 项通过，仍只有基线记录的 6 项失败和 11 项报错，没有新增回归。当前正式线路第一次检测不合格后必须在同一家庭路径完整复测；一次失败后恢复只记为 `UNKNOWN`，两次都不合格才记为 `BAD`。测试模拟 8 台同时不合格时生成 8 项替换决定，证明没有“最多 6 台”限制；模拟 12 台大面积同时异常时整轮熔断且替换数为 0。好线路即使存在评分更高的备份也保持不动，备份切换前复验失败会立即移出池。

### 4. AC86U 直连 GitHub（已完成）

- [x] 路由器通过现有家庭分流主动连接 GitHub，不开放家庭入站端口。
- [x] 使用仅限本仓库、可单独撤销的写入凭据；不保存账号级令牌。
- [x] 路由器只提交家庭报告/决策，正式分支留给下一阶段的受保护 GitHub 工作流发布。
- [x] GitHub 连接失败时在 U 盘保留本地报告并延后重试，正式清单保持不变。

阶段结果：远端已建立只含说明文件的独立 `home-reports` 分支（初始提交 `2bad257c7caf7a4939184527d0701837a4016431`）。AC86U 使用仓库专用 Ed25519 Deploy Key，经 `ssh.github.com:443` 主动推送；GitHub 官方主机指纹、仓库名和报告分支均锁死，不接受账号令牌、未知主机密钥或其他目标。待发报告入队和推送前都会校验版本、探针编号、大小、内容哈希与文件名，失败或并发冲突时保留 U 盘队列并从新克隆重试。Deploy Key 本身是仓库级而不是分支级，因此 `protected_publishing_ready=false` 是硬停机销：Phase 5 未完成默认分支保护和发布器前，即使误开推送也会失败关闭。

阶段专项测试 10 项全部通过；全仓库共 188 项，171 项通过，仍为基线已有的 6 项失败和 11 项报错，没有新增回归。

## 续做规则

1. 每次开始先读取本文件和分支最新提交，不依赖聊天记忆猜进度。
2. 每完成一个阶段就勾选对应项目、记录测试命令和结果，并单独提交。
3. 自动采集若继续更新 `master`，先把变更合并到本分支，再进入下一阶段。
4. 未通过阶段验收时，不进入下一阶段的生产启用动作。
5. 路由器未现场验证前，所有仓库代码只能处于未激活或影子模式。
