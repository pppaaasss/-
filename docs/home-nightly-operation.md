# 每日夜间新源检测

北京时间每天 02:00–11:00 检测待测新源。13:00–16:00 和 20:00–23:00 保持现用源复查，不派发新源检测。配置中已撤销 2026-09-20 的下午临时续跑。

夜间先测现用源，异常项再测一次，然后逐批处理尚未测过的新源。合格的新源立即写入 `home-control/state.json` 的 `archive` 备份池；已测身份进入 `tested` 并离开 `queue`。两次明确失败的现用源才可由合格源替换，UNKNOWN 不作为换源依据。正式订阅仍走受保护的发布 PR。

## 额度和收尾

- 每晚根据待测身份建立持久化 `night_plan`。11 点前新到的候选会追加；如果本轮已经结束，新候选会唤醒本轮，保留现用源检查和已测结果。
- 新源流量预算按每批最多四条、64 MiB 计算，并保留一个批次的余量；至少保持原来的 6 GiB。另保留原有 2 GiB 供现用源和备份检查使用。同一天的额度保留到晚间，避免已发生的夜间用量挤掉正常复查。
- 新源时间预算覆盖完整九小时窗口，总时间额度覆盖当天现有的十五小时检测窗口。任务有效期仍限制在各自窗口内，11 点以后不发新源任务。
- HTTP 状态或质量字段异常时，源仍为 UNKNOWN；单独验证的字节计数和已完成批次的起止时间可正常结算。字节未知时保留整批字节预留；中断批次和历史未知用量仍不退还未证实的资源。
- 到 11 点时，只要现用源检查及必要复查完整，就保存已有备份、生成已有合格替换决策。`candidate_queue_remaining` 明确记录剩余数；只有剩余为零才标记 `candidate_sweep_complete`。未测项留在持久队列，次日 02 点自动继续。

原生采样每批 240 秒、四条、64 MiB，以及 58/50 MiB 可用内存、16 MiB 进程组 RSS 和 CPU 保护均保持原值。真实断网、路由器保护暂停或待测量超过九小时可处理的数量时，状态必须保留未完成数量，不能把窗口结束当成全测完。

## 验证依据

回归覆盖 875 条候选在模拟批次和云端交接耗时下完成，保留未知字节的整批预留但结算已验证时间，确认只保存合格备份且不替换正常频道；另覆盖新候选唤醒、11 点收尾、延迟到下午的收尾、次日继续、白天禁发候选，以及不完整现用源检查不能产生可发布报告。模拟结果不冒充家庭现场测量。
